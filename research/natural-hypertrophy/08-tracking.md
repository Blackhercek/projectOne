# 08 · Измерения и автопилот: как узнать, что план работает

> «Я вроде расту» — это не данные. Без измерений вы не отличите работающий протокол
> от неработающего и потратите месяцы на диагностику того, что решается за 10 минут в неделю.

---

## 8.1 Что измерять и как часто

| Метрика | Частота | Как правильно | Зачем |
|---|---|---|---|
| **Вес** | Каждое утро | Натощак, после туалета, без одежды, те же весы | Основной сигнал энергобаланса |
| **Скользящее среднее веса за 7 дней** | Раз в неделю | Среднее последних 7 замеров | Убирает шум воды/гликогена/ЖКТ |
| **Обхваты** | Раз в 2 недели | Утром, без напряжения: талия на уровне пупка, грудь, бицепс в напряжении, бедро, шея | Отличает мышцы от жира |
| **Фото** | Раз в 4 недели | Одно место, свет, поза, время суток, минимум одежды: фас/профиль/спина | Самый честный источник |
| **Рабочие веса и повторы** | Каждая тренировка | В лог, каждый рабочий подход | Доказательство прогрессии |
| **e1RM ключевых упражнений** | Раз в 2 недели | Формула ниже | Тренд силы без тестирования 1ПМ |
| **Сон** | Ежедневно | Часы в постели; приложение/трекер опционально | Главный фактор восстановления |
| **Самочувствие/мотивация** | Ежедневно | 1–5 баллов, одно число | Ранний детектор перетренированности |
| **Пульс покоя** | Ежедневно утром | До подъёма с кровати | Детектор накопленной усталости |

### Почему скользящее среднее, а не «вес сегодня»

Суточные колебания веса **±1–2 кг** — это вода, гликоген, содержимое ЖКТ и соль.
При целевом приросте 200 г/нед сигнал в **5–10 раз меньше шума**. Скользящее среднее
за 7 дней снижает шум примерно в √7 ≈ 2.6 раза и делает тренд читаемым.

```
MA7(день N) = (вес[N] + вес[N-1] + ... + вес[N-6]) / 7
Δ за неделю = MA7(сегодня) − MA7(7 дней назад)
```

## 8.2 Формулы, которые понадобятся

### Оценка одноповторного максимума (e1RM)

**Эпли:**
```
e1RM = вес × (1 + повторы / 30)
```

**Бжицки (точнее до 10 повторов):**
```
e1RM = вес × 36 / (37 − повторы)
```

Пример: 100 кг × 8 повторов → Эпли: 126.7 кг; Бжицки: 124.1 кг.
Используйте **одну** формулу постоянно — важен тренд, а не абсолютная точность.

**Поправка на RIR:** если подход был на RIR 2, считайте как `повторы + 2`
(это оценка «повторов до отказа»).

### Фактический TDEE из данных

```
TDEE = средние_ккал_в_день − (Δвеса_кг × 7700) / число_дней
```

Пересчитывайте каждые 3–4 недели: TDEE меняется вместе с весом и адаптацией.

### Целевой темп набора

```
Целевой прирост в неделю (кг) = текущий_вес × целевой_процент / 100
```

| Стаж | Целевой % | Для 75 кг | Для 90 кг |
|---|---|---|---|
| Новичок | 0.25–0.5 % | 190–375 г | 225–450 г |
| Средний | 0.1–0.25 % | 75–190 г | 90–225 г |
| Опытный | 0.05–0.15 % | 40–110 г | 45–135 г |

### Оценка состава прироста

Быстрая прикидка по обхватам: если **талия растёт быстрее, чем (грудь + бедро)/2** —
доля жира в приросте слишком велика. Снизьте профицит на 150–200 ккал.

### FFMI

```
FFM  = вес × (1 − %жира/100)
FFMI = FFM / рост(м)² + 6.1 × (1.8 − рост(м))
```

## 8.3 Дерево решений (еженедельный аудит)

**Каждое воскресенье, 10 минут.** Идите по дереву сверху вниз, остановитесь на первом «да».

```
┌─ Пропустил > 15 % тренировок за 4 недели?
│   └─ ДА → Проблема не в программе. Упростите её (меньше дней, короче сессии).
│            Адгерентность — уровень 1 пирамиды. Всё остальное подождёт.
│
├─ MA7 веса не изменился за 2 недели (± 0.3 %)?
│   └─ ДА → +150–250 ккал/день (лучше углеводами). Пересчитайте TDEE.
│
├─ MA7 растёт быстрее целевого темпа 2 недели подряд?
│   └─ ДА → −150–250 ккал/день. Проверьте обхват талии.
│
├─ Вес растёт по плану, но рабочие веса/повторы стоят 3+ недели?
│   ├─ Сон < 7 ч?           → ДА → Это причина. Чините сон, не трогайте программу.
│   ├─ RIR честно 0–3?      → НЕТ → Вы работаете слишком далеко от отказа. Калибруйте.
│   ├─ Объём < 10 подходов? → ДА → Добавьте 2–4 подхода на группу.
│   ├─ Объём > 20 и падает качество? → ДА → Снимите 3–5 подходов, часто это «мусорный объём».
│   └─ Всё выше в норме     → Делоуд 5–7 дней, затем смена 1–2 упражнений.
│
├─ Есть 2+ признака из [чек-листа восстановления](06-recovery.md#67-признаки-того-что-восстановление-не-успевает)?
│   └─ ДА → Делоуд 5–7 дней. Калории не снижать.
│
├─ Боль в суставе/сухожилии держится > 1 недели?
│   └─ ДА → Замените упражнение на аналог по вектору, снизьте амплитуду в болевой зоне,
│            не «терпите». При сохранении > 3 недель — к врачу.
│
├─ % жира вырос выше 18 % (муж) / 28 % (жен)?
│   └─ ДА → Завершите набор, мини-сушка 6–10 недель, затем новый блок набора.
│
└─ Всё в норме?
    └─ Ничего не менять. Продолжать. Это самый частый правильный ответ.
```

> **Главное правило автопилота: менять только одну переменную за раз и давать ей 2 недели.**
> Если вы одновременно добавили калории, объём и поменяли сплит — вы не узнаете,
> что сработало, и не сможете это повторить.

## 8.5 Контрольные точки: чего ждать по неделям

| Точка | Что должно произойти | Если нет |
|---|---|---|
| **Неделя 2** | Определены рабочие веса, лог заполняется, MA7 считается | Проблема системы, а не тела |
| **Неделя 4** | MA7 вырос на ~1 % от массы тела; веса выросли в 50 %+ упражнений | Проверьте калории по формуле фактического TDEE |
| **Неделя 8** | +2–3 % массы тела; e1RM основных движений +5–10 %; фото показывают разницу | Идите по дереву решений |
| **Неделя 12** | +3–5 % массы тела; заметная разница на фото; все упражнения прогрессировали | Полный аудит уровней 1–5 пирамиды |
| **Неделя 20** | +5–8 % массы тела (новичок), +3–4 % (средний); талия +≤ 2 см | Пора планировать мини-сушку |

## 8.6 Типичные ошибки измерений

| Ошибка | Почему плохо | Как правильно |
|---|---|---|
| Взвешиваться раз в неделю | Одна точка = максимум шума | Каждый день, смотреть на MA7 |
| Смотреть на вес после читмила | +1.5 кг воды и гликогена | Игнорировать, смотреть тренд |
| Биоимпедансные весы как истина | Погрешность ±3–5 % по жиру | Использовать только тренд, не абсолют |
| Фото в разном свете и позе | Несравнимо | Метка на полу, один свет, одно время |
| Мерить бицепс каждый день | Меняется от пампа | Раз в 2 недели, в одинаковом состоянии |
| Тестировать 1ПМ каждый месяц | Стоит дней восстановления | Считать e1RM из рабочих подходов |
| Не записывать RIR | Нельзя оценить качество стимула | Одна цифра на подход |
| Менять 3 переменные сразу | Невозможно атрибутировать результат | Одна переменная, 2 недели |

## 8.7 Автоматизация

В папке [`tools/`](tools/) лежит калькулятор на Node.js без зависимостей:

```bash
# Полный расчёт плана
node tools/hypertrophy-calc.mjs \
  --sex=m --age=28 --height=180 --weight=75 --bodyfat=15 \
  --activity=moderate --level=intermediate

# Пересчёт фактического TDEE по вашим данным
node tools/hypertrophy-calc.mjs tdee --kcal=2800 --days=14 --start=75.0 --end=75.6

# Оценка e1RM
node tools/hypertrophy-calc.mjs e1rm --weight=100 --reps=8 --rir=2
```

Выдаёт: BMR, TDEE, целевые калории и макросы, распределение белка по приёмам,
целевой темп набора, недельные объёмы подходов и прогноз на 12/24/52 недели.

## Итоги раздела

1. Вес — каждый день, решения — по скользящему среднему за 7 дней.
2. Лог тренировок обязателен: вес × повторы × RIR. Без него прогрессия — фантазия.
3. Еженедельный аудит по дереву решений — 10 минут, экономит месяцы.
4. Меняйте одну переменную за раз и давайте ей 2 недели.
5. Самый частый правильный ответ аудита — «ничего не менять, продолжать».
